# Julien Hughes-John (Ju)

**Full-Stack Principal AI Systems Architect | Governed, bounded AI platforms that run on any model | Agent operating systems, knowledge graphs, MCP**

AI systems architect specialising in the control, governance and execution layers around language models. My architectural approach is governed systems architecture: integrating knowledge, permissions, constraints, execution and evidence into one governed system.

I treat AI as a way to speed up processes, not as something to trust, so every system I build governs and checks what the model does. I design and build enterprise AI platforms that screen inputs, authorise actions, verify outputs and keep auditable records, independently of the model being used.

## What I build

### Governed AI platforms

- A self-hosted AI systems platform: an IDE, an AI executive team that delegates, and a 3D office it is run from by voice
- Governed execution: every model call and tool call passes boundaries, checks and approvals before it runs, and is recorded as evidence
- Model-independent architecture: the knowledge, rules and permissions live outside the model, so a cheaper model can do the same work
- AI-time estimation: AI work estimated in AI time and cost from the platform's own past runs, not human days

### Governed data intake

- Data admitted only from sources a person has approved, with a record of what came in, from where, and why anything was refused
- Every column judged from the schema before any of its values may enter an organisation's knowledge; each decision recorded with why it was made, and revisited when the rules change
- 93,633 records from Kafka and Flink streams, company accounts and bank statements taken in; on a test database, 17,681 of 106,672 values withheld

### Workflows that applications become part of

- A visual workflow environment in which applications themselves become workflow steps, with an agent that turns plain-language requirements into executable workflows
- Database migrations across PostgreSQL, MySQL, Oracle and Azure SQL: the AI plans from structure, and customer records never leave the customer's estate
- Branching processes, AI agents as steps, approvals, and outside services, messaging and data sources

### Regulated software in production

- An offline-first fire-door compliance platform delivered to a client through on-site integration testing
- An AI workflow studio for accountancy firms: approvals, evidence and Making Tax Digital for VAT across a firm's clients

### Code intelligence

- Repository understanding for AI agents: symbols, call graphs and dependencies across every repository, kept live as code changes

## How I work

- **Design from failure first.** Start from what could go wrong and follow each consequence until it is accounted for.
- **Architecture from first principles.** Work out the problem and its constraints, then derive the architecture, rather than adopting a pattern by default.
- **Explicit boundaries of authority.** What an agent may decide alone, what needs human approval, and what it must never do.
- **Completeness through traceability.** A result that works is not yet understood until its inputs, decisions, rules and outcomes can be traced back to their origins.
- **Show the capability, protect the implementation.**
